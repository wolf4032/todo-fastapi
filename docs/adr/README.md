# 設計判断の記録（ADR）

ADR（Architecture Decision Record）は、設計上の判断を1件につき1ファイルで残す軽量な文書。コードを読めば「何をしたか」は分かるが、「なぜそうしたか」「他に何を検討して、なぜ採らなかったか」はコードに残らない。それを後から辿れるようにするためのもの。

## 書き方

各 ADR は次の見出しで書く（Michael Nygard の形式を元に「却下した案」を独立させたもの）。

- **ステータス**: 提案 / 採用 / 廃止 / 置き換え（→ 後継の番号）
- **背景**: 判断が必要になった状況と、満たしたい要件
- **決定**: 何を決めたか
- **却下した案**: 検討したが採らなかった案と、その理由
- **結果**: この決定で得たものと、引き受けたトレードオフ

## 運用のルール

- **採用済みの ADR は書き換えない。** 判断を変えるときは新しい番号で ADR を書き、古い方のステータスを「置き換え（→ 00XX）」にする。当時の判断と理由が履歴として残ることに価値があるため
- 番号は連番で、欠番を作らない
- 仕組みの詳しい説明は `docs/notes/` に任せ、ADR には判断とその根拠だけを書く
