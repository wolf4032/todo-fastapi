# async/await・並行処理

Step 5 で `async def` の関数と `await` を実際に書いた際に整理した一般知識。Python固有の話が多いが、他言語との比較も含める。

## コルーチンとは何か

`async def` で定義した関数を呼び出しても、中身は1行も実行されない。返ってくるのは「まだ実行されていない予約票」（コルーチンオブジェクト）で、関数呼び出し1回分の実行状態（どこまで進んだか、ローカル変数の中身）をまるごと閉じ込めたもの。行単位の概念ではない。

```python
async def greet():
    print("A")
    await asyncio.sleep(1)
    print("B")

async def main():
    coro = greet()        # ここでは "A" は表示されない。予約票が作られるだけ
    print("呼び出し直後")   # これが先に表示される
    await coro             # ここで初めて中身が動き出す
```

**Python特有の挙動**であることに注意。JavaScriptの `async function` は、呼び出した瞬間に中身が同期的に実行され始め、最初の `await` にぶつかった時点でようやく `Promise` を返して制御を戻す。「呼んでも即座には動かない」のはPythonの方だけ。

## `await` が「ブロックする」の正確な意味

`await` の後の行が、その処理が終わるまで実行されないのは、`await` の有無に関係なく**常に成り立つ、当たり前の性質**（普通の同期コードと同じ）。ここに `await` の特別さはない。

`await` の本当の役割は関数の**外**で起きる。`await` で一時停止している間、そのスレッドは**イベントループに返却され**、他の待機中のコルーチン（別のリクエストの処理など）に使われる。同期のブロッキング呼び出しは、待っている間そのスレッドを完全に専有し、他の何にも使わせない。この「待っている間、スレッドを他の仕事のために手放せるかどうか」だけが、同期と非同期の違い。

2つの `await` に挟まれたコードは、他のどのコルーチンにも中断されずに一気に実行される（協調的マルチタスク。横取りは起きない）。中断が起こり得るのは `await` と書かれた、その瞬間だけ。裏を返すと、`await` を挟まない長い同期処理を `async def` の中に書くと、他の全コルーチンをブロックしてしまう。

## 並行処理（concurrency） ≠ 並列処理（parallelism）

- **並列処理**: 複数のCPUコアを使い、文字通り同時刻に複数の処理を進める
- **並行処理**: 実行単位を細かく切り替えることで、見かけ上同時に進んでいるように見せる（同時刻に動いているのは常に1つだけ、という場合を含む）

`asyncio` は並行処理であり、並列処理ではない。スレッドは1本のまま、待っている間に他のコルーチンへ切り替えるだけで、CPUコアを複数使っているわけではない。

## FastAPIでの実務上の注意

FastAPIは `def`（同期関数）のエンドポイントを自動的に別スレッドで実行してくれる（`run_in_threadpool`）。一方 `async def` はイベントループ上で直接動く。

**`await` を1つも使わない `async def` は、`def` より危険。** 中に本物の非同期待機が無いのに時間のかかる同期処理（重い計算、同期ライブラリでのDBアクセスなど）を書くと、一時停止のポイントが無いため、その処理が終わるまでイベントループ全体（＝他の全リクエスト）が完全に固まる。「`async def` にする」＝「中に本物の `await` がある」がセットで初めて意味を持つ。

## 既知のギャップ: uvicornのアクセスログはJSON化されていない

"GET /health/db HTTP/1.1" 200 OK` という行はそのままの形式で残る。統一するには `--log-config` でuvicorn側のロギング設定ごと差し替える必要があるが、今回は対応していない。
