# React / Next.js のコンポーネントの種類と `useEffect`

Step 15 で TODO 画面を書いた際に整理した一般知識。

## どこで動くか

ページを「開いて」いるのはブラウザ。Next.js のサーバー（このリポジトリでは `web` コンテナ内の Node.js）は、リクエストを受けて HTML や RSC Payload を作って返す側で、ページを表示しているわけではない。相対 URL の基準になる「今開いているページ」はブラウザにしか無い（→ [step-15-todo-page.md](step-15-todo-page.md)）。

## コンポーネントの呼び方

| 書き方 | 呼び方 | どこで動くか |
|---|---|---|
| ファイル先頭に `"use client"` | Client Component | 初回はサーバーで HTML にし、その後ブラウザでも動く |
| 何も書かない | 読み込み方次第 | 下記 |

**`"use server"` はコンポーネント用ではない**。付けたファイルの関数を **Server Function**（Next.js では Server Action とも呼ぶ）にする指定で、ブラウザから呼ぶとサーバーで実行される関数になる。フォームの送信先などに使う。Server Component を作るための指定は存在しない。

### 何も書かないコンポーネント

App Router では、指定の無いコンポーネントは既定で **Server Component** として扱われる。ただし `"use client"` のファイルから import されると、そのファイルごとクライアント側（Client Component の一部）に取り込まれる。

つまり指定の無いファイルは「自分で決めない」だけで、**誰が読み込むかで、どちら側で動くかが決まる**。どちらからも使えるように書いたものを、Next.js の文書では shared component（共有コンポーネント）と呼んでいる。

- `page.tsx` / `layout.tsx` から直接使う → Server Component
- `todo-app.tsx`（`"use client"`）から import する → Client Component の一部

## `useEffect`

**画面を描いた後に実行したい処理**を登録する仕組み。

コンポーネントの関数は「state から画面（JSX）を計算する」ものとして、state が変わるたびに React が何度も呼び直す。ここに API の呼び出しを直接書くと、次のループになる。

```
描画 → fetch → 応答で setTodos → state が変わったので再描画 → また fetch → …
```

さらに、初回はサーバーでも関数が呼ばれるので、ブラウザ専用の処理はそこで動かせない。`useEffect` に渡した関数は、**ブラウザで描画が終わった後にだけ**呼ばれる。画面の計算とは別の、外の世界とのやり取り（API 呼び出し・タイマー・イベントの購読など）を置く場所。こうした外とのやり取りを「副作用（side effect）」と呼ぶのが名前の由来。

### 第2引数（依存配列）

| 書き方 | いつ実行されるか |
|---|---|
| 省略 | 描画のたび毎回 |
| `[]` | 最初に画面に出たときだけ |
| `[a, b]` | 最初と、`a` か `b` が変わったとき |

### 後片付け

`useEffect` に渡した関数が関数を `return` すると、それが後片付けとして呼ばれる。呼ばれるのは次の2つのとき。

- コンポーネントがアンマウントされるとき（下記）
- 依存配列の値が変わって、もう一度実行する直前

`todo-app.tsx` では、ここで `ignore = true` にしている。開発時の Strict Mode は、わざと「実行 → 後片付け → 実行」を1回余分に行い、後片付けの書き忘れを表に出す。

### もう一度実行されるのはいつか

`[]` を指定していても、`useEffect` は次のときに「後片付け → もう一度実行」される。

| きっかけ | 本番 | 開発 |
|---|---|---|
| 依存配列の値が変わった（`[]` なら起きない） | ○ | ○ |
| アンマウントされた（後片付けだけ。`[]` でも起きる） | ○ | ○ |
| 最初に画面に出た直後（Strict Mode） | — | ○ |
| ソースを編集して保存した（Fast Refresh） | — | ○ |

- **Strict Mode**: ソースの変更とは関係なく、最初に画面に出た直後に1回だけ「アンマウント → マウント」を擬似的に起こす。本番でも、別の画面へ移って戻ってくれば同じことが起きる。後片付けを書き忘れた `useEffect` はそのとき壊れるので、開発中に先に起こして見つけやすくしている
- **Fast Refresh**: 保存した変更を画面に反映するために、`[]` でも `useEffect` を実行し直す（Next.js の文書 `03-architecture/fast-refresh.md`）

### アンマウントとは

React が組み立てている画面の構成（コンポーネントの木）から、そのコンポーネントが取り除かれること。逆に加わることをマウントと呼ぶ。`[]` が止めるのは「依存配列の変化による再実行」だけなので、アンマウント時の後片付けは `[]` でも必ず呼ばれる。

- **起きる**: 別のページへ移動した・`{条件 && <X />}` の条件が偽になった・一覧から要素が消えた（`key` が無くなった）
- **起きない**: スクロールして見えなくなった・ウィンドウの裏に隠れた。DOM はそのまま残っていて、React から見ると何も変わっていない

「見えているかどうか」で何かしたいときは、ブラウザの `IntersectionObserver` などを自分で使う。

### 後片付けは応答を待たない

後片付けは、そのきっかけが来た時点ですぐに呼ばれる。送った GET の応答が届いているかどうかは関係ない。GET 自体は取り消されずに進み、応答は後から届く。

### `ignore` が止めるもの

`let ignore` は `useEffect` に渡した関数の中で宣言しているので、**実行1回ごとに新しく作られ、その回の中でだけ使われる**。後片付けの関数も `.then()` の関数も同じ回の中で作られるので、同じ `ignore` を見ている（外側の変数を覚えたまま後から呼ばれる関数を、クロージャと呼ぶ）。

Strict Mode で2回動いたときの、時間の順の流れ:

```
1回目の実行 : ignore₁ = false、GET を送る（A）
後片付け    : ignore₁ = true（A の応答はまだ届いていない）
2回目の実行 : ignore₂ = false、GET を送る（B）
A の応答が届く → ignore₁ が true なので捨てる
B の応答が届く → ignore₂ が false なので setTodos する
```

応答が届く順番は送った順とは限らない（B が先に届くこともある）。`ignore` があれば、どちらの順でも**最後に実行した回の応答だけ**が state に入る。依存配列に値を入れた場合（検索語が変わるたびに取得し直す、など）にも同じ問題が起き、同じ書き方で防げる。

「初回だけ取得する」のは `[]` の役目で、`ignore` ではない。追加・更新・削除の `setTodos` は `useEffect` の外にあるので、`ignore` とは関係なく毎回反映される。

応答を捨てるのではなく、GET そのものを途中で取り消すこともできる（`AbortController`）。今回は捨てるだけで困らないので、単純な方にした。

## 描き直しが起きるタイミング

React は画面を一定間隔（60FPS など）で計算し直しているわけではない。**`setTodos` などの更新関数が呼ばれたとき**に、そのコンポーネントの関数を呼び直して JSX を計算し直す（再レンダー）。`{loading ? ... : ...}` が評価されるのもこのときだけ。

- 計算し直した結果を前回と比べ、**変わった部分の DOM だけ**を書き換える
- 近いタイミングで呼ばれた複数の更新関数は、まとめて1回の再レンダーにされる（batching）
- `useEffect` が終わったこと自体は再レンダーのきっかけにならない。中で更新関数を呼んだから描き直される
- 依存配列が `[]` なので、再レンダーしても `useEffect` はもう一度は動かない

ブラウザ自体は60FPS前後で画面を塗り直しているが、それは描いた DOM を表示する側の話で、React の再レンダーとは別。

TODO 画面の流れ:

```
1. 初回レンダー: todos = []、loading = true → 「読み込み中…」
2. 描画後に useEffect が動き、GET を送る
3. 応答が届く → setTodos / setTotal / setLoading(false)
4. 再レンダー: loading = false → 一覧を表示
```
