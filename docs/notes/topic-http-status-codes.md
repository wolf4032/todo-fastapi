# HTTP ステータスコード

HTTP の応答の1行目に入る3桁の数字。**百の位で大分類**が決まっていて、細かい番号を知らなくても、百の位だけで「誰が何をすべきか」が分かるようになっている。

## 大分類

| 百の位 | 意味 | 誰の問題か | 同じリクエストを送り直すと |
|---|---|---|---|
| 1xx | 途中経過 | — | （普段のアプリでは意識しない） |
| 2xx | 成功 | — | — |
| 3xx | 別の場所を見て（リダイレクト） | — | ブラウザが自動で移動先へ行く |
| 4xx | リクエストが悪い | **送った側（クライアント）** | 同じ結果になる。直してから送る |
| 5xx | サーバーが処理できなかった | **受けた側（サーバー）** | 時間をおけば成功するかもしれない |

4xx と 5xx を分けてある理由は、右端の列にある。4xx は「このリクエストのままでは何度送っても駄目」、5xx は「リクエストは悪くないかもしれない、こちらの都合で失敗した」。自動で再試行するかどうかを、中身を読まずに番号だけで判断できる。

## このアプリで出てくるもの

| コード | 名前 | 意味 | このアプリで出る場面 |
|---|---|---|---|
| 200 | OK | 成功。本文に結果がある | 一覧取得・1件取得・更新（PATCH） |
| 201 | Created | 成功して、新しく作った | 作成（POST）。本文は作った TODO |
| 204 | No Content | 成功。返す本文は無い | 削除（DELETE） |
| 307 / 308 | Temporary / Permanent Redirect | 別の URL へ（一時的 / 恒久的） | 末尾に `/` を付けた `/api/v1/todos/` を送ったとき。api に直接送ると FastAPI が 307、web 経由だと rewrites より先に Next.js が 308 を返し、どちらも `/api/v1/todos` へ移動させる。公開環境では `http://` で来たリクエストを Caddy が 308 で `https://` へ移動させる（→ [step-19-https.md](step-19-https.md)）。301 / 302 と違い、307 / 308 は POST などのリクエストの種類と本文を変えずに送り直させる |
| 404 | Not Found | 対象が無い | 存在しない id・存在しない URL |
| 405 | Method Not Allowed | その URL はあるが、そのメソッドは受け付けない | `/api/v1/todos` に PUT を送る |
| 422 | Unprocessable Content | 形式は読めたが、中身が決まりを満たさない | `title` が空・`limit=0` など Pydantic の検証に落ちた |
| 500 | Internal Server Error | サーバー内部で想定外の失敗 | api の未処理例外（DB に繋がらないなど）。`api` が止まっているときに Next.js が返すのもこれ |
| 502 / 503 / 504 | Bad Gateway / Service Unavailable / Gateway Timeout | 中継役から見て、奥のサーバーが変な応答をした・いない・遅すぎる | 今は出ない。本番で前段にリバースプロキシを置くと出うる |

将来ユーザー認証を足すと、次の2つも出てくる。

| コード | 名前 | 意味 |
|---|---|---|
| 401 | Unauthorized | 誰なのか分からない（未ログイン・トークンが無効） |
| 403 | Forbidden | 誰かは分かったが、その操作の権限が無い |

## 400 と 422 の違い

どちらも「リクエストが悪い」だが、FastAPI では次のように使い分けている。

- **400 Bad Request**: そもそも読めない（壊れた JSON など）。汎用の「リクエストが悪い」
- **422**: JSON としては読めたが、「`title` は1文字以上」のような決まりを満たさない

FastAPI は壊れた JSON も 422 で返す（本文の解析と検証をまとめて Pydantic に任せているため）。どちらも「送った側が直す」4xx なので、クライアントの扱いはほぼ同じでよい。

## 画面側での扱い

`fetch` はどの番号でも「応答が届いた」として成功扱いにする。番号をどう解釈するかはアプリが決める（→ [step-15-todo-page.md](step-15-todo-page.md)）。

| 分類 | このアプリの画面の扱い |
|---|---|
| 2xx | 返ってきた値で画面の状態を更新する |
| 404 | 一覧から取り除き、「すでに削除されていました」と出す |
| 422 | `details` の項目ごとの理由を並べて出す |
| その他の 4xx / 5xx | API が返した `message` を出す |
| 応答なし | 「サーバーに接続できません」と出す |
